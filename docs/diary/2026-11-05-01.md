# Diary — 2026-11-05 (01)

## Numbers and duplicate keys on aemi's primitives

The decimal scan (`scanDecimal`, `scanPaddedDecimal`, `exactExponent`) and `LongDecimal` moved to aemi as `DecimalScanner` and
`DecimalFloat.double(_:in:)` / `float(_:in:)` (aemi ADR 0031), shared with AemiHMMML's TOML and, later, YAML. What stays here is
JSON's own: the JSON5 spellings, integers, hexadecimal. `NumberFastPathTests` still holds the fast paths to padded decimals, and
caught two gaps in aemi's first version (zeros folded eight at a time in the zero-aware pass; a short `Float` with trailing zeros),
fixed there.

The first measurement was a regression: canada.json's full value tree took 14 % more instructions. Fixed in aemi, not here (a
six-word literal, an inlinable fast pass, an overlapping tail load, the first three integer digits byte by byte). Now, with
`AemiJSONProbe` normalised by Foundation's time in the same run (the machine's load varied; three interleaved runs, medians):
every workload within ±3 % of before, memory the same or lower; per number on canada, 320 instructions and 17 ns against 320 and 18.

The duplicate-key check (`.throwError`) hashes keys with aemi's `KeyedHash` (SipHash-1-3 under the process key) instead of
`Hasher`: the same defence, at under half the cost on a short key.

Pins: aemi 88e2e27, AemiRegex af5a281. 509 tests pass.
